\section{Empirical Validation}\label{sec:validation}

The experiments test a single claim: under continuous drift, memory must be
regulated by temporal usefulness rather than by statistical evidence of abrupt
change alone. The empirical story has three parts. First, the Gaussian sweep
recovers the cube-root law itself. Second, continuous-drift benchmarks show that
classical adaptive windows can keep too much stale memory. Third, the
piecewise-drift benchmark shows that a cube-root cap can recover the local
oracle horizon across regimes.

\subsection{Law Validation}\label{sec:validation_law}

We begin with the Gaussian sweep used to validate the finite-memory law. The
setup produces the characteristic U-curve: for small windows, error is dominated
by variance; for large windows, error is dominated by staleness. The empirical
minimum follows the predicted cube-root scaling, and EWMA behaves as the natural
finite-memory analogue rather than as a competing theory.

\begin{figure}[!htbp]
\centering
\safeincludegraphics[width=0.92\linewidth]{figures/fig_ucurve}
\caption{Cube-root validation on the Gaussian sweep. Left: tracking error as a
function of window size, showing the predicted U-shape for multiple drift rates.
Right: the minimum achievable error follows an approximate $\zeta^{1/3}$ law.
This figure validates the structural trade-off between variance and staleness
that underlies the rest of the paper.}\label{fig:ucurve}
\end{figure}

\subsection{Lag--Variance Frontier}\label{sec:validation_frontier}

The U-curve becomes more informative when it is viewed as a frontier in horizon
space. The next figure plots tail error against effective memory horizon for a
fixed-window sweep and overlays the operating points of the main methods. The
curve is asymmetric: on the left, extra memory still buys a visible reduction in
noise; on the right, extra memory mainly adds age. The knee is where that trade
stops paying off.

\begin{figure}[!htbp]
\centering
\safeincludegraphics[width=0.95\linewidth]{figures/cuberoot_adwin/fig_lag_variance_frontier}

memory validity distinct from the evidence threshold for abrupt change.

\subsection{Fixed-Horizon Instability}\label{sec:validation_instability}

The next benchmark is designed to make fixed-horizon instability visible. The
stream alternates between slow drift, fast bursts, recovery plateaus, and
micro-bursts with irregular durations, so the local oracle horizon need not be
globally stable. In that setting, a single fixed window can look reasonable on
average while remaining locally misaligned for long stretches. This benchmark
separates three questions that are often conflated: whether the oracle horizon
is time-varying, whether an online regulator can track that changing scale, and
how far each method remains from the local oracle horizon over time.

\begin{figure}[!htbp]
\centering
\safeincludegraphics[width=0.95\linewidth]{figures/cuberoot_adwin/fig_horizon_instability}
\caption{Alternating-timescales instability. The top panel shows the drift
schedule, the middle panel shows the local oracle horizon alongside fixed
windows and the cube-root regulator, and the bottom panel shows horizon regret
\,$|n_t - n_t^*|\,$ over time. The purpose of the benchmark is to expose when
the useful horizon changes locally: slow stretches favor longer memory, bursts
contract the oracle scale, and fixed horizons can remain misaligned across
regime changes.}
\label{fig:horizon_instability}
\end{figure}

This benchmark makes the gap between prediction error and horizon validity
visible. A short fixed window can still remain competitive in aggregate error
while being misaligned with the local oracle scale. The observed asymmetry is
clear: contraction of the useful horizon is easier to trigger than re-expansion
after a low-drift stretch. The alternating-timescales benchmark quantifies the
same pattern directly.

The benchmark also points to path dependence in temporal memory adaptation.

\subsection{Horizon Cost Curve}\label{sec:validation_gap_cost}

The next question is when horizon misalignment becomes operationally expensive.
For each backend, we compare its instantaneous horizon $n_t$ with the local
cube-root target $n_t^*$ and plot the excess error $E_t - E_t^\star$ against both
the absolute gap $|n_t - n_t^*|$ and the relative gap $|\log(n_t / n_t^*)|$.
Here $E_t^\star$ is the best error achieved at time $t$ by the fixed-window oracle
grid, and the curve is binned over all seeds and time points.

\begin{figure}[!htbp]
\centering
\safeincludegraphics[width=0.95\linewidth]{figures/cuberoot_adwin/fig_horizon_gap_cost}
\caption{Excess error as a function of horizon misalignment. The relation is
backend dependent rather than universal: fixed-100 stays inside a low-cost band,
whereas fixed-500 and ADWIN pay substantially more once the gap widens. The cube-
root regulator sits between these extremes, which is consistent with the paper's
claim that horizon validity and predictive payoff are related but not identical.}
\label{fig:horizon_gap_cost}
\end{figure}

The main lesson is not that error is a monotone function of horizon gap for every
backend. The lesson is that the paper now exposes a measurable tolerance band
around the useful-memory scale, together with backend-specific degradation once
that band is exceeded.

The central distinction is between statistical detection and temporal validity.
Statistical detection asks whether there is enough evidence to declare a change.
Temporal validity asks whether the memory being used is still fresh enough to
count as current. The cap-only regime makes that gap visible.

\subsection{What the Figures Show}\label{sec:validation_summary}

Taken together, the figures support three claims. First, the cube-root law is a
real finite-memory law rather than a fitting artifact. Second, adaptive windows
that optimize detection can still accumulate too much stale memory under smooth
drift. Third, horizon validity and predictive optimality are related but not
identical: the cube-root cap gives an explicit operational rule for regulating
memory near the oracle scale, but the predictive payoff of that regulation is
regime-dependent and backend-dependent.
